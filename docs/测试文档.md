# 测试文档

## 1. 文档说明

本文档用于记录 TravelOn 旅游服务平台的测试目标、测试环境、测试范围、测试用例、测试结果和问题记录。内容以当前仓库实现为准。

## 2. 测试目标

本次测试目标如下：

1. 验证前端页面能够正常访问。
2. 验证后端 Docker Compose 能够正常启动。
3. 验证 PostgreSQL、MongoDB、RabbitMQ 等基础设施可用。
4. 验证服务注册、网关路由和主要业务接口可用。
5. 验证用户、酒店、交通、订单、支付、社区、AI 行程规划等核心功能流程。
6. 验证系统在常见异常输入下能给出合理反馈。

## 14.1 代码覆盖率

三套工具各自采集，`tests/run_tests.py` 在 unit / all / ci / full 结束后统一聚合：

| 层 | 工具 | 主指标 | 采集时机 |
|---|---|---|---|
| Java（7 个模块） | JaCoCo 0.8.12 | 指令覆盖率 / 分支覆盖率 | `mise run test:unit` 里的 `mvn -DexcludedGroups=pre test jacoco:report jacoco:check` |
| Agent 服务（Python） | pytest-cov | 行覆盖率 / 分支覆盖率 | `pytest tests/unit --cov-fail-under` |
| 前端 | Jest（react-scripts） | 语句覆盖率 / 分支覆盖率 | `yarn test:unit:coverage` |

### 查看方式

聚合结果写入 `artifacts/test-results/`（CI 产物里同样包含）：

- `latest.md` 的「覆盖率」表格：每个模块的主指标、分支指标和报告路径。
- `summary.json` 的 `coverage` 字段：机器可读，便于比对历史。
- `artifacts/test-results/coverage/{java,java-it,python,ui}/`：各工具的原始报告副本。

集成阶段的 JaCoCo 数据写在 `target/site/jacoco-it/`，在表格里以「集成」口径单列，不与单元覆盖率混算。

### 阈值

阈值按接入门禁时的实测值下调约 5 个百分点设定，**目的是防止倒退，不是追求高数字**。任一模块低于阈值时构建直接失败。

统计口径只含单元测试：`pre` 阶段的前置守卫用 `-DexcludedGroups=pre` 排除在外，集成阶段的覆盖率单列在 `java-it` 一行。

| 模块 | 指令 / 行 | 分支 |
|---|---|---|
| user-service | 55% | 42% |
| ai-arrange-service | 55% | 35% |
| api-gateway | 0%（无单元测试，唯一的 `*Test` 已归入 pre 阶段） | 不设 |
| discovery-service | 0%（无单元测试，只有 IT） | 不设 |
| community-service | 25% | 20% |
| travel-core-service | 18% | 20% |
| order-service | 15% | 15% |
| ai-arrange-agent-service | 48%（`--cov-fail-under`） | — |
| travel-ui | 语句 58% | 35% |

阈值定义位置：各模块 `pom.xml` 的 jacoco `rules`、`travel-ui/package.json` 的 `jest.coverageThreshold`、`tests/run_tests.py` 的 `PYTHON_COVERAGE_MINIMUM`。补齐测试后应同步上调，避免阈值长期停在过时的低位。

## 16. 测试结论

本次测试覆盖系统部署、服务发现、网关路由、前端访问、用户账户、酒店交通查询、订单支付、社区功能和 AI 行程规划等核心流程。测试结果表明，系统能够在 Docker Compose 环境下正常启动，PostgreSQL、MongoDB、RabbitMQ 和各业务服务运行正常，前端页面可访问，Eureka 中核心服务均为 UP，Gateway 能正确转发业务接口。

用户注册登录、酒店与交通查询、订单查看与支付、社区浏览与发布、AI 行程规划等主要页面流程均符合预期。AI 行程规划依赖外部模型和地图 API Key，未配置外部 Key 时可展示页面和依赖说明，不影响系统其他功能使用。
