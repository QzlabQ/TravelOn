# 测试文档

## 1. 文档说明

本文档用于记录 TravelOn 旅游服务平台的测试目标、测试环境、测试范围、测试用例、测试结果和问题记录。内容以当前仓库实现为准，历史 PDF 中的需求和设计仅作为测试范围参考。

课程提交时，可将本文档补充实际测试结果和截图后导出为 PDF，命名为：

```text
X组-测试文档.pdf
```

## 2. 测试目标

本次测试目标如下：

1. 验证前端页面能够正常访问。
2. 验证后端 Docker Compose 能够正常启动。
3. 验证 PostgreSQL、MongoDB、RabbitMQ 等基础设施可用。
4. 验证服务注册、网关路由和主要业务接口可用。
5. 验证用户、酒店、交通、订单、支付、社区、AI 行程规划等核心功能流程。
6. 验证系统在常见异常输入下能给出合理反馈。

## 4. 当前实现测试重点

当前主线相比旧设计文档有以下变化，测试时需要按当前实现验证：

| 项目 | 测试关注点 |
|---|---|
| 数据库初始化 | PostgreSQL 是否执行 `database/init` 下 SQL |
| 表结构校验 | Spring JPA `ddl-auto=validate` 是否通过 |
| 数据导入 | `database/seed` 中初始数据是否可被查询 |
| 服务注册 | Gateway 和业务服务是否注册到 Eureka |
| 网关路由 | `/hotels/**`、`/transports/**`、`/users/**` 等路径是否可用 |
| 旧 data-generator | 当前主线已移除，不再作为测试项 |
| AI 规划 | 依赖 MongoDB、AI agent 和外部模型 Key |

## 6. 测试方法

本次测试采用手工测试为主，结合命令行状态检查和浏览器页面验证。

常用命令：

```bash
cd travel-api
docker compose ps
docker compose logs --tail=100 gateway
docker compose logs --tail=100 postgres
docker compose logs --tail=100 discovery
```

前端检查：

```bash
cd travel-ui
yarn start
```

浏览器访问：

```text
http://localhost:53000
```

## 15. 问题记录

| 编号 | 问题描述 | 影响范围 | 处理方式 | 状态 |
|---|---|---|---|---|
| BUG001 | Docker Hub 镜像拉取慢 | 部署启动 | 配置镜像源或提前拉取镜像 | 待确认 |
| BUG002 | 网关根路径返回 404 | 部署验证 | 属于正常现象，网关只配置业务路由 | 已确认 |
| BUG003 | 旧数据库导致表结构不一致 | 后端启动 | 删除 `data/postgres` 后重新初始化，或执行 cleanup 脚本 | 待确认 |
| BUG004 | AI 规划无法生成 | AI 模块 | 检查外部模型 API Key 和网络 | 待确认 |
