# 部署文档

## 1. 文档说明

本文档用于说明 TravelOn 旅游服务平台的部署环境、部署步骤、配置项、验证方式和常见问题。文档内容以当前仓库实现为准。

## 2. 项目概述

TravelOn 是一个面向旅游出行场景的前后端分离系统，提供酒店查询、交通票务查询、旅游产品聚合、预订、支付、账号管理、社区分享和 AI 行程规划等功能。系统采用 React 前端、Spring Cloud 微服务后端、Docker Compose 容器化部署，并使用 PostgreSQL、MongoDB 和 RabbitMQ 等基础设施支撑业务运行。

## 3. 当前实现与历史设计差异

历史设计文档中出现过 H2、data-generator、服务侧 CSV 自动导入等设计，但当前仓库已经完成数据库与数据初始化重构，实际部署时应按当前代码执行。

| 项目 | 当前实现 |
|---|---|
| 前端 | `travel-ui`，React + TypeScript + MUI |
| 网关 | `api-gateway`，统一转发 HTTP 与 WebSocket 请求 |
| 服务发现 | `discovery-service`，Eureka |
| 业务服务 | hotel、transport、offer-provider、reservation、payment、user、community、ai-arrange |
| AI agent | `ai-arrange-agent-service`，FastAPI |
| 关系型数据库 | PostgreSQL，按服务拆分数据库 |
| AI 规划数据库 | MongoDB |
| 消息队列 | RabbitMQ |
| 社区上传目录 | `travel-api/data/community/uploads`，持久化用户上传图片 |
| 数据初始化 | PostgreSQL entrypoint 执行 `travel-api/database/init` 下 SQL |
| 表结构策略 | Spring JPA 默认 `ddl-auto=validate`，只校验表，不自动建表 |
| 旧 data-generator | 已从当前主线移除 |

## 6. 后端部署

### 6.1 进入后端目录

```bash
cd travel-api
```

### 6.2 配置后端环境变量

在 `travel-api` 目录下创建 `.env` 文件：

```env
DEEPSEEK_API_KEY=
AMAP_API_KEY=
DEEPSEEK_MODEL=
DEEPSEEK_FLASH_MODEL=deepseek-v4-flash
DEEPSEEK_PRO_MODEL=deepseek-v4-pro
DEEPSEEK_THINKING_TYPE=disabled
DEEPSEEK_MAX_TOKENS=12000
DEEPSEEK_SLOW_RESPONSE_WARNING_MS=60000
```

其中 AI 行程规划依赖 `DEEPSEEK_API_KEY`，地图增强能力依赖 `AMAP_API_KEY`。如果课程展示不演示真实 AI 生成，可先留空并说明外部 API 未配置。

### 6.3 启动后端

```bash
docker compose up -d --build
```

### 6.4 查看后端状态

```bash
docker compose ps
```

正常结果：

- Postgres 显示 `healthy`
- MongoDB、RabbitMQ、Eureka、Gateway 和各业务服务显示 `Up`
- Gateway 映射到 `58082`
- Eureka 映射到 `58010`

## 7. 数据库初始化说明

当前主线使用 PostgreSQL SQL 脚本初始化数据库。首次启动时，PostgreSQL 容器会在数据目录为空时自动执行 `travel-api/database/init`。

目录结构如下：

```text
travel-api/database/
  init/
    001-create-service-databases.sql
    010-apply-service-schema-and-seed.sql
  schema/
    hotel_schema.sql
    transport_schema.sql
    user_schema.sql
    reservation_schema.sql
    community_schema.sql
  seed/
    hotel_seed.sql
    transport_seed.sql
    user_seed.sql
    community_seed.sql
  cleanup/
    *.sql
```

初始化过程：

1. 创建 `hotel_db`、`transport_db`、`user_db`、`reservation_db`、`community_db`、`payment_db`
2. 切换到各服务数据库
3. 执行 schema 脚本建表
4. 执行 seed 脚本导入初始数据
5. Spring 服务启动后使用 `ddl-auto=validate` 校验表结构

当前社区数据库还包含帖子、评论、景点、旅游路线、收藏、图片 URL 等表结构。社区服务将用户上传图片保存到容器内 `/uploads`，并通过 Docker Compose 挂载到宿主机：

```text
travel-api/data/community/uploads
```

如果本地已有旧数据目录，PostgreSQL entrypoint 不会重复执行 init 脚本。需要重建数据库时执行：

```bash
cd travel-api
docker compose down
rm -rf data/postgres
docker compose up -d --build
```

注意：该操作会删除本地 PostgreSQL 数据，仅适用于开发和课程演示环境。

如果遇到无法解释的数据库、MongoDB 或 RabbitMQ 状态问题，当前主线的 `!!!important.md` 要求重置三类持久化目录后重建：

```bash
cd travel-api
docker compose down
rm -rf data/postgres data/mongo data/rabbitmq
docker compose up -d --build
```

该命令会删除本地 PostgreSQL、MongoDB 和 RabbitMQ 数据，执行前应确认不需要保留本地演示数据。

## 8. 前端部署

### 8.1 进入前端目录

```bash
cd travel-ui
```

### 8.2 配置前端环境变量

本地开发配置：

```env
REACT_APP_API_HOSTNAME=localhost
REACT_APP_API_PORT=58082
REACT_APP_AMAP_JS_API_KEY=
REACT_APP_AMAP_SECURITY_JS_CODE=
```

远程服务器部署时，将 `REACT_APP_API_HOSTNAME` 改为服务器公网 IP 或域名：

```env
REACT_APP_API_HOSTNAME=服务器公网IP
REACT_APP_API_PORT=58082
```

说明：React 的 `REACT_APP_*` 变量会在构建时写入静态文件，修改 `.env` 后必须重新构建前端。

### 8.3 本地开发方式启动

```bash
yarn install
yarn start
```

访问：

```text
http://localhost:53000
```

### 8.4 Docker 方式启动

```bash
docker build -t travel-ui .
docker run -d --name travel-ui --restart unless-stopped -p 80:80 travel-ui
```

访问：

```text
http://服务器公网IP
```

## 10. 常用运维命令

查看服务状态：

```bash
cd travel-api
docker compose ps
```

查看日志：

```bash
docker compose logs --tail=100 gateway
docker compose logs --tail=100 discovery
docker compose logs --tail=100 hotel
docker compose logs --tail=100 transport
docker compose logs --tail=100 reservation

```

```bash
docker compose restart
```

停止全部后端服务：

```bash
docker compose down
```

重新构建：

```bash
docker compose up -d --build
```

## 11. 常见问题

### 11.1 Docker 镜像拉取慢

如果 Docker Hub 拉取失败或过慢，可配置 Docker 镜像加速，或在演示前提前拉取镜像。

### 11.2 后端启动后数据库表不存在

检查 `travel-api/data/postgres` 是否已经存在旧数据。如果存在，PostgreSQL 不会重新执行初始化脚本。开发环境可删除该目录后重建：

```bash
docker compose down
rm -rf data/postgres
docker compose up -d --build
```

### 11.3 前端请求后端失败

检查：

- `travel-ui/.env` 中 API 地址是否正确
- 后端 Gateway 是否运行
- 云服务器安全组是否开放 `58082`
- 前端 `.env` 修改后是否重新构建

### 11.4 AI 行程规划无法生成

检查：

- `DEEPSEEK_API_KEY` 是否配置
- `ai-arrange-agent` 是否运行
- `ai-arrange-service` 是否能访问 MongoDB 和 agent
- 外部模型接口是否可访问

### 11.5 社区图片上传后无法显示

检查：

- `travel-api/docker-compose.yml` 是否挂载 `./data/community/uploads:/uploads`
- `community-service` 是否设置 `APP_UPLOADS_DIR=/uploads`
- 图片 URL 是否通过 `/community/uploads/**` 访问
- 云服务器部署时是否开放 Gateway 端口 `58082`

## 12. 部署结论

本项目可通过 Docker Compose 完成后端微服务、PostgreSQL、MongoDB、RabbitMQ 和 AI agent 的统一部署，通过 React 开发服务或 Nginx 容器提供前端页面。当前实现采用 SQL 脚本初始化数据库，并由 Spring JPA 校验表结构，适合课程展示和复现实验环境。
