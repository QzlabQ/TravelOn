# 部署文档

## 1. 文档说明

本文档用于说明“旅游服务平台”项目的部署环境、部署步骤、配置说明和部署验证结果。课程提交时可将本文档补充实际截图后导出为 PDF，命名为“X组-部署文档.pdf”。

## 2. 项目概述

本项目为旅游服务平台，包含前端页面、API 网关、服务发现、用户服务、酒店服务、交通服务、订单服务、支付服务、社区服务、AI 行程规划服务，以及数据库和消息队列组件。

系统主要组成如下：

| 模块 | 说明 |
|---|---|
| travel-ui | 前端页面，提供用户访问入口 |
| api-gateway | API 网关，统一转发前端请求 |
| discovery-service | 服务发现组件 |
| user-service | 用户注册、登录、用户资料管理 |
| hotel-service | 酒店查询、酒店详情 |
| transport-service | 交通票务查询 |
| offer-provider-service | 旅游产品报价聚合 |
| reservation-service | 预订、订单、取消、退款 |
| payment-service | 支付相关功能 |
| community-service | 社区帖子、评论、点赞 |
| ai-arrange-service | AI 行程规划业务服务 |
| ai-arrange-agent-service | AI agent 服务 |
| PostgreSQL | 关系型数据库 |
| MongoDB | AI 行程规划数据存储 |
| RabbitMQ | 消息队列 |

## 5. 后端部署步骤

### 5.1 进入后端目录

```bash
cd travel-api
```

### 5.2 配置后端环境变量

在 `travel-api` 目录下创建 `.env` 文件：

```env
DEEPSEEK_API_KEY=
AMAP_API_KEY=
DEEPSEEK_MODEL=
DEEPSEEK_FLASH_MODEL=deepseek-v4-flash
DEEPSEEK_PRO_MODEL=deepseek-v4-pro
DEEPSEEK_THINKING_TYPE=disabled
DEEPSEEK_MAX_TOKENS=12000
DEEPSEEK_SLOW_RESPONSE_WARNING_MS=60000
```

说明：

| 变量名 | 说明 |
|---|---|
| DEEPSEEK_API_KEY | AI 行程规划所需 API Key，可为空 |
| AMAP_API_KEY | 高德地图后端接口 Key，可为空 |
| DEEPSEEK_MODEL | 默认模型名 |
| DEEPSEEK_FLASH_MODEL | Flash 模型名 |
| DEEPSEEK_PRO_MODEL | Pro 模型名 |
| DEEPSEEK_THINKING_TYPE | 推理模式配置 |
| DEEPSEEK_MAX_TOKENS | 最大输出 token 数 |
| DEEPSEEK_SLOW_RESPONSE_WARNING_MS | 慢响应提示阈值 |

### 5.3 构建并启动后端服务

```bash
docker compose up -d --build
```

### 5.4 查看后端服务状态

```bash
docker compose ps
```

正常情况下，各服务状态应显示为 `Up`，PostgreSQL 应显示为 `healthy`。

## 6. 前端部署步骤

### 6.1 进入前端目录

```bash
cd travel-ui
```

### 6.2 配置前端环境变量

在 `travel-ui` 目录下创建 `.env` 文件：

```env
REACT_APP_API_HOSTNAME=localhost
REACT_APP_API_PORT=58082
REACT_APP_AMAP_JS_API_KEY=
REACT_APP_AMAP_SECURITY_JS_CODE=
```

如果部署到远程服务器，需要将 `REACT_APP_API_HOSTNAME` 改为服务器公网 IP 或域名。

示例：

```env
REACT_APP_API_HOSTNAME=服务器公网IP
REACT_APP_API_PORT=58082
```

### 6.3 本地开发方式启动前端

```bash
yarn install
yarn start
```

访问地址：

```text
http://localhost:53000
```

### 6.4 Docker 方式启动前端

```bash
docker build -t travel-ui .
docker run -d --name travel-ui --restart unless-stopped -p 80:80 travel-ui
```

访问地址：

```text
http://服务器公网IP
```

## 7. 部署验证

### 7.1 验证前端页面

在浏览器访问：

```text
http://localhost:53000
```

或远程服务器：

```text
http://服务器公网IP
```

页面能正常打开，即说明前端部署成功。

### 7.2 验证后端网关

API 网关地址：

```text
http://localhost:58082
```

说明：网关根路径 `/` 可能返回 404，这是因为网关只配置了业务路由，如 `/hotels/**`、`/users/**`、`/community/**` 等，不代表服务异常。

### 7.3 验证服务发现

访问 Eureka 控制台：

```text
http://localhost:58010
```

如果能看到各个服务注册信息，说明服务发现正常。

## 8. 常用运维命令

查看服务状态：

```bash
cd travel-api
docker compose ps
```

查看指定服务日志：

```bash
docker compose logs --tail=100 gateway
docker compose logs --tail=100 user
docker compose logs --tail=100 hotel
```

重启服务：

```bash
docker compose restart
```

停止服务：

```bash
docker compose down
```

重新构建并启动：

```bash
docker compose up -d --build
```

## 9. 常见问题

### 9.1 Docker 镜像拉取慢或失败

如果 Docker Hub 拉取较慢，可将基础镜像切换到国内可访问的镜像源，或配置 Docker 镜像加速。

### 9.2 前端请求后端失败

检查 `travel-ui/.env`：

```env
REACT_APP_API_HOSTNAME=localhost
REACT_APP_API_PORT=58082
```

如果是远程服务器部署，应改为服务器公网 IP 或域名，并重新构建前端。

### 9.3 服务器安全组无法访问

如果远程服务器部署后无法访问，需要检查云服务器安全组是否开放：

- 80
- 58082
- 58010
- 22

## 10. 部署结论

本项目通过 Docker Compose 完成后端微服务、数据库、消息队列和 AI 服务的统一部署，通过前端开发服务或 Nginx 容器提供用户访问页面。部署完成后，前端页面可正常访问，后端服务可通过 API 网关调用，各微服务可在服务发现中心完成注册。
