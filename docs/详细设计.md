### 当前数据设计调整

旧版详细设计中出现的 H2、data-generator 和部分待联调状态已经过期。当前数据设计为：

- PostgreSQL 通过 `travel-api/database/init` 初始化业务库和表结构。
- `hotel_db`、`transport_db`、`user_db`、`reservation_db`、`community_db`、`payment_db` 按服务拆分。
- MongoDB 保存 AI 规划会话、消息和快照。
- RabbitMQ 用于部分服务间消息通信。
- 社区上传图片通过 `travel-api/data/community/uploads` 做宿主机持久化。

### 当前关键流程

1. 用户通过前端访问页面，所有业务请求统一进入 Gateway。
2. Gateway 根据路径转发到酒店、交通、用户、社区、订单、支付或 AI 服务。
3. 普通业务服务读写 PostgreSQL，AI 规划服务读写 MongoDB。
4. AI 规划页面通过 Java `ai-arrange-service` 创建会话并保存快照；Java 服务调用 Python Agent 生成规划结果。
5. 未配置外部模型或地图 Key 时，AI 页面仍可展示，并通过配置说明或 fallback 保证演示链路不影响其他模块。

## 2 系统结构设计及子系统划分
### 2.1 系统总体结构

系统采用浏览器前端 + Spring Cloud 微服务 + 消息总线 + 独立 AI 服务的结构。浏览器只访问 API Gateway，Gateway 根据路径将请求转发到具体服务。业务服务注册到
Eureka，服务间主要通过 RabbitMQ 交换数据。AI 行程规划服务使用 MongoDB 保存会话、消息和快照。

订单与住宿         酒店/民宿订单关联一个住宿实体及一个或多个房型库存项；入住日期区间不得与已锁定库存冲突。

订单与交通         票务订单关联一个或多个去返程班次及座位数量；剩余座位不足时不得创建锁定。

订单与支付         一个订单只有一个有效支付结果；支付成功后状态不可回退为待支付。

订单与价格         订单创建时保存成交价格快照，列表展示订单价格而不是当前查询价格。

### 5.2 故障预防与补救

- 服务注册：所有后端服务注册到 Eureka，Gateway 通过服务名访问，避免固定实例地址。
- 消息解耦：酒店、交通、预订、支付通过 RabbitMQ 降低直接耦合。
- Saga 补偿：预订失败、支付失败或支付超时时，删除已创建的酒店预订、交通预订和 reservation。
- AI 降级：未配置 DeepSeek API Key 时返回本地占位响应；快照抽取失败时使用 fallback Markdown。
- 会话恢复：AI 前端将会话信息缓存到 localStorage，刷新页面后重新查询服务器快照。
- 数据版本：AI 快照按 version 保存，用户可回看历史版本。
- 容器化部署：Docker Compose 固定服务依赖关系，保证基础服务先启动。

### 5.3 系统维护设计

- 配置维护：服务配置集中在各模块 application.properties 和 api-gateway/application.yml。

- 密钥维护：DEEPSEEK_API_KEY、AMAP_API_KEY、DEEPSEEK_MODEL 等通过 .env 注入，不应提交到代码仓库。
- 日志维护：服务默认输出 Spring 日志，compose 中可挂载日志目录。
- 数据维护：PostgreSQL、MongoDB 和 RabbitMQ 均通过 Docker Compose 挂载卷持久化，演示前需确认卷目录和初始化脚本。
- 数据集维护：原始历史数据文件只读保存，查询投影或新增中国数据使用独立导入批次和来源标识，避免覆盖原始数据。
- 接口维护：前端 API 封装集中在 apiConfig.tsx，后端路由集中在 Gateway 配置中，修改路径时需同步更新。
- 测试维护：Java 服务使用 Maven 测试，Python Agent 使用 pytest，前端可使用 React Testing Library。

## 6 性能优化和安全设计
### 6.1 性能优化设计

- Gateway 统一入口减少前端服务地址感知，服务实例可横向扩展。
- 酒店、交通、预订等服务采用独立进程，避免单个业务阻塞整个系统。
- 产品聚合服务通过 RabbitMQ 请求酒店和交通数据，避免强绑定数据库。
- AI 聊天使用 WebSocket 流式返回，降低用户首屏等待。
- AI 快照生成异步接续在流式对话之后，避免阻塞文本输出。
- MongoDB 快照中内嵌 places 和 routes，减少查询时多表关联。
- 交通容量检查使用现有预订集合计算剩余座位，避免复杂事务锁。
- 前端 AI 会话使用本地缓存，减少页面刷新后的重复创建。

### 6.2 安全设计

- API Key 使用环境变量注入，.env 文件只在部署环境保存。
- Gateway 配置 CORS 以支持课程演示；生产环境应收紧 allowed origins。
- AI 会话所有查询和 WebSocket 连接都使用 conversationId + userId 校验归属。
- WebSocket 建连时缺少 conversationId 或 userId 直接关闭连接。
- REST 请求使用 DTO 接收参数，AI 会话创建和更新接口使用 @Valid 校验。
- 支付流程当前为模拟支付，不存储真实银行卡敏感数据。
- RabbitMQ 消息仅在后端内部网络中使用，生产环境应开启账号密码和网络隔离。
- 用户身份当前主要依赖 userId 传参，后续应接入登录态、JWT 或 Session 认证。
- 预定列表、详情与取消接口接入登录后必须以服务端认证用户为准，不信任前端自行提交的 userId。
- 历史真实数据集若包含外部来源字段或用户痕迹，导入展示前应去除个人敏感信息，仅保留住宿、交通和价格等业务字段。

### 6.3 部署与运行设计

- 本地后端使用 travel-api/docker-compose.yml 启动 RabbitMQ、MongoDB、Eureka、Gateway 和各业务服务。
- 部署环境可使用 travel-api/docker-compose-deploy.yml 拉取镜像运行。
- 前端使用 yarn start 开发运行，使用 yarn build 构建生产包。
- Java 服务使用 Maven 构建，Dockerfile 位于各服务目录。
- Python Agent 使用 uvicorn app.main:app --host 0.0.0.0 --port 8090 运行。
- 当前 compose 中存在 Windows 绝对路径卷挂载，换机部署时需要调整为本机路径。
