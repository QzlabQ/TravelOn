# 票务种子数据

## 中文

日期化票务数据由 `../scripts/generate_dated_ticket_offers.py` 根据以下模板生成：

- `transport/train/ticket_offers.csv`
- `transport/plane/ticket_offers.csv`

实际导入 PostgreSQL 的文件是对应目录下的 `generated_ticket_offers.csv`。

模板由 `../scripts/generate-ticket-offers.py` 维护。它补齐城市两两之间缺失的航线与车次，并为部分航班派生商务舱和头等舱。座位等级在 CSV 中是独立的行：商务舱约覆盖 45% 的航班，头等舱约覆盖 20%，由航班号哈希确定。

模板价格是线路基准价。按日期展开时，每个“班次、舱位或席别、日期”组合会在基准价上下浮动约 20%。浮动使用确定性哈希，因此相同输入会生成完全相同的 CSV。

售票窗口以生成当天为基准滚动，默认为前 3 天至后 38 天。`tests/test_seed_window.py` 会在 `mise run test:pre` 中检查提交的数据是否仍覆盖“今天 + 30 天”。

### 修改售票窗口

调整 `../scripts/generate_dated_ticket_offers.py`：

```python
WINDOW_START_OFFSET = timedelta(days=-3)
WINDOW_END_OFFSET = timedelta(days=38)
```

每增加一天，两个生成文件各增大约 1 MB。

在仓库根目录重新生成数据：

```powershell
mise exec -- python travel-api/scripts/generate_dated_ticket_offers.py
```

如果 Docker Compose 已在运行，在 `travel-api` 目录导入现有数据库并重启服务：

```powershell
docker compose exec -T postgres psql -U admin -d travel_core_db -f /database/seed/transport_seed.sql
docker compose restart travel-core
```

如果 `.env` 修改过数据库用户名或 `TRAVEL_CORE_DB_NAME`，需要替换命令中的 `admin` 和 `travel_core_db`。票务种子脚本会先清理旧模板再导入，避免同一班次同一天同时保留新旧价格。

`mise run services:up_build` 只重新构建镜像。已有 `travel-api/data/postgres` 时不会自动重新生成或导入 CSV；修改数据后仍需显式执行上述导入命令。

验证导入后的日期范围：

```powershell
docker compose exec postgres psql -U admin -d travel_core_db -c "SELECT type, MIN(departure_date_time), MAX(departure_date_time), COUNT(*) FROM ticket_offer_templates GROUP BY type;"
```

跨午夜的火车班次可能在一天出发、次日到达，属于正常数据。

## English

Dated ticket data is generated by `../scripts/generate_dated_ticket_offers.py` from:

- `transport/train/ticket_offers.csv`
- `transport/plane/ticket_offers.csv`

The corresponding `generated_ticket_offers.csv` files are imported into PostgreSQL.

`../scripts/generate-ticket-offers.py` maintains the templates, fills missing routes between cities, and derives business- and first-class rows for selected flights. Seat classes are separate CSV rows. Roughly 45% of flights receive business class and 20% receive first class, determined by a flight-number hash.

Template prices are route baselines. Expansion varies each service, class, and date combination by up to 20% using a deterministic hash, so identical input produces identical CSV output.

The booking window rolls relative to generation time and defaults to 3 days back through 38 days ahead. `tests/test_seed_window.py`, run by `mise run test:pre`, verifies that committed data still covers today plus 30 days.

### Changing the booking window

Edit `../scripts/generate_dated_ticket_offers.py`:

```python
WINDOW_START_OFFSET = timedelta(days=-3)
WINDOW_END_OFFSET = timedelta(days=38)
```

Each additional day adds roughly 1 MB to each generated file.

Regenerate from the repository root:

```powershell
mise exec -- python travel-api/scripts/generate_dated_ticket_offers.py
```

If Docker Compose is running, import into the existing database and restart the service from `travel-api`:

```powershell
docker compose exec -T postgres psql -U admin -d travel_core_db -f /database/seed/transport_seed.sql
docker compose restart travel-core
```

Replace `admin` and `travel_core_db` if `.env` overrides the database credentials or `TRAVEL_CORE_DB_NAME`. The seed script clears old templates before importing so a service and date cannot retain both old and new prices.

`mise run services:up_build` only rebuilds images. When `travel-api/data/postgres` already exists, it does not regenerate or import the CSV files; run the import explicitly after changing the data.

Verify the imported date range:

```powershell
docker compose exec postgres psql -U admin -d travel_core_db -c "SELECT type, MIN(departure_date_time), MAX(departure_date_time), COUNT(*) FROM ticket_offer_templates GROUP BY type;"
```

Overnight trains may depart on one day and arrive on the next; that is expected.
